# Onboarding Guide — Vijay Niles' Blog

Welcome. This document gets you from "I just cloned this" to "I can confidently make changes and ship them." It's written to build up layer by layer: first the big picture, then the stack, then how each piece fits, then the workflows you'll actually use, and finally the sharp edges to watch out for.

Everything here was verified against the source code, not just the config comments. Where the setup differs from what you'd naively expect, it's flagged.

---

## 1. The 30-Second Summary

This is a **static blog** built with [Hugo](https://gohugo.io/), a Go-based static site generator. You write posts in Markdown, Hugo compiles them into plain HTML/CSS/JS, and the result is hosted on **GitHub Pages** at `https://www.vijayniles.com/`.

- **No backend, no database, no server runtime.** Everything is pre-rendered HTML.
- **Theme:** [PaperMod](https://github.com/adityatelange/hugo-PaperMod), pulled in as a git submodule.
- **Deployment:** fully automated via GitHub Actions on every push to `main`.
- **Dynamic-feeling features** (comments, newsletter, search) are all handled client-side by third-party services or JavaScript, not a server.

The mental model: **you edit Markdown and a little HTML/CSS → Hugo turns it into a folder of static files → GitHub serves that folder.**

## 2. Tech Stack

| Layer | Technology | Notes |
|---|---|---|
| Site generator | **Hugo** (extended), pinned to `v0.146.0` | Version pinned in CI; `baseof.html` hard-errors if Hugo < 0.146.0 |
| Theme | **PaperMod** | Git submodule at `themes/PaperMod` |
| Content | **Markdown** | Posts use TOML front matter (`+++`), page-type content uses YAML front matter (`---`) |
| Styling | **CSS** | Dart Sass is installed in CI (PaperMod uses SCSS internally); your custom overrides are plain CSS |
| Templating | **Go HTML templates** | Hugo's templating language, used in the `layouts/` overrides |
| Hosting | **GitHub Pages** | Custom domain via `CNAME` |
| CI/CD | **GitHub Actions** | `.github/workflows/hugo.yml` |
| Comments | **Disqus** | Client-side embed, shortname `vijayniles` |
| Newsletter | **Kit / ConvertKit** | Client-side embedded form |
| Search | **Fuse.js** (via PaperMod) | Client-side fuzzy search over a generated JSON index |

### The one concept that makes Hugo "click": override by mirroring

Hugo looks for templates in **your project's `layouts/` first, then falls back to the theme's `themes/PaperMod/layouts/`.** To customize anything from the theme, you copy its file into the same relative path under your own `layouts/` and edit it. That's exactly what's been done here:

- `layouts/_default/single.html` overrides the theme's post template (to inject the newsletter).
- `layouts/partials/comments.html` overrides the theme's comments partial (to wire up Disqus with theme-aware dark mode).
- `extend_head.html` and `extend_footer.html` are PaperMod's official extension hooks — they're *meant* to be created in your project, and PaperMod injects them automatically. You don't need to override anything to use them.

Same idea for CSS: `assets/css/extended/custom.css` is a PaperMod convention. Any CSS you drop in `assets/css/extended/` gets bundled into the final stylesheet automatically. You never fork the theme's core CSS.

## 4. How the Pieces Fit Together (Request → Render)

Walk through what happens when someone visits a blog post:

1. **GitHub Pages** serves a pre-built HTML file from `public/` (e.g., `public/posts/.../index.html`).
2. That HTML was generated by Hugo from a Markdown file in `content/posts/`, wrapped in the templates:
   - `baseof.html` provides the `<html>`/`<head>`/`<body>` skeleton.
   - `single.html` fills in the `main` block with the post title, meta, content, tags, share buttons, newsletter, and comments.
3. **Client-side**, three things come alive in the browser:
   - **Reading progress bar** — the inline script in `extend_head.html` listens to scroll and widens `.reading-progress-bar`. Only runs on single-post pages (`.IsPage`).
   - **Newsletter form** — loads Kit's `ck.5.js` and renders the embedded ConvertKit form (only on `posts` section pages — see the `eq .Section "posts"` guard in `single.html`).
   - **Disqus comments** — loads `vijayniles.disqus.com/embed.js`, and re-themes itself when the user toggles light/dark mode.

The flow for building the site locally or in CI:

```
content/*.md  ──┐
layouts/*     ──┤
assets/css/*  ──┼──►  hugo  ──►  public/  ──►  GitHub Pages
themes/PaperMod ┘        (compiles templates + markdown + bundles CSS/JS)
config.yml    ──┘
```

## 5. Configuration Deep Dive (`config.yml`)

This file is where most behavior is tuned without touching templates. Key things to know:

- **`baseURL`** / **`title`** / **`copyright`** — site identity.
- **`theme: [PaperMod]`** — tells Hugo to use the submodule theme.
- **`mainsections: ["posts"]`** — the homepage lists posts from `content/posts/`.
- **`outputs.home`** includes `JSON` — this is what generates the **search index** that Fuse.js consumes. Without the JSON output, search breaks.
- **`menu.main`** — the nav bar items and their order via `weight`. The first item, "Join the course waitlist!", is an external CTA: it uses a negative `weight` to sit first, a `pre: "👉"` emoji, and `params.cta: true` which the `header.html` override turns into standout orange styling. External menu links (URL with `://`) get `target="_blank" rel="noopener noreferrer"` from the override.
- **`taxonomies`** — `category`, `tag`, `series` are enabled. Posts currently use `tags`.
- **`params`** — the big one. Toggles for reading time, share buttons, breadcrumbs, ToC, code-copy buttons, comments, etc. Notable:
  - `disqusShortname: "vijayniles"` lives under `params` (not top-level). The commit history shows this was deliberately moved here so templates can read it via `.Site.Params.disqusShortname` — don't move it back to the top level or Disqus breaks.
  - `defaultTheme: dark` — dark is the default (matching the Kit brand look). The light/dark toggle still works; the user's choice is saved in `localStorage`.
  - `hideAuthor: true`, `ShowShareButtons`, `ShareButtons: [linkedin, reddit, x, email]`.
  - `assets.disableHLJS: true` — highlight.js is disabled; syntax highlighting uses Hugo's built-in Chroma (`pygmentsUseClasses: true` + the `markup.highlight` block).
- **`markup.goldmark.renderer.unsafe: true`** — allows raw HTML inside Markdown. Needed for embeds, but means Markdown content is trusted. Keep that in mind for anything user-generated (there isn't any today).

## 6. The Custom Styling Story (`custom.css`)

This is the most actively-developed file in the repo. The styling is a **brand port of the Kit landing page** (`go.vijayniles.com`): dark navy, AWS orange accent, Montserrat typography. How it's built matters:

- **Theming is done by overriding PaperMod's own CSS variables**, not by fighting individual selectors. PaperMod drives every surface off tokens like `--theme`, `--entry`, `--primary`, `--secondary`, `--content`, `--border`. The file remaps those for both `:root` (light) and `:root[data-theme="dark"]` (dark), plus adds brand tokens `--accent` (`#ff9900`), `--accent-hover`, and `--heading`. This is the single most important thing to understand: **change a color by changing a variable, not by writing a new rule.**
- **No `!important`.** Because we theme through variables, the file is free of the `!important` soup an earlier version had. If a style isn't applying, look for a missing/overridden variable first, not specificity.
- **Fonts** (Montserrat + Domine) are loaded in `layouts/partials/extend_head.html` and applied via `font-family` in the CSS.
- **Both themes stay on-brand.** Dark mode = the exact Kit look (default). Light mode keeps navy ink + orange accent for consistency.
- The file is organized into commented sections: design tokens, typography, accents, reading progress bar, Disqus container, newsletter form, header CTA, and homepage intro spacing. Each section explains *why* it exists — several rules exist specifically to counteract a PaperMod default (e.g. the homepage `.first-entry.home-info` spacing fix).
- **Still test both themes** when touching color-sensitive components (newsletter title, Disqus). A couple of rules need an explicit dark-mode counterpart.

## 7. ⚠️ Sharp Edges — Read This Before You Build

These are the things that will trip you up. All verified against the actual repo state.

### 7.1 The theme is a git submodule — initialize it after cloning
`themes/PaperMod/` is a submodule. A fresh clone won't have its contents until you run:

```bash
git submodule update --init --recursive
```

**Hugo will fail to build until you do this.** (CI already does `submodules: recursive` on checkout, so this only matters locally.)

### 7.2 Hugo is pinned per-project — don't rely on a global install
Hugo is **not** installed globally. It's pinned via the `hugo-extended` npm package (see `package.json`) and installed into `node_modules/` by `npm install`. Run it through the npm scripts (`npm run dev`, `npm run build`) or `npx hugo`. This keeps your local version exactly matched to CI (**Hugo Extended `0.146.0`**). `baseof.html` hard-errors below that version, and the *extended* edition is required for PaperMod/Dart Sass.

### 7.3 `public/` is build output — git-ignored, never edited by hand
`public/` is generated by Hugo and rebuilt from scratch by CI on every push. It's listed in `.gitignore` and is **not** tracked. Never edit it directly or commit it; change the source (`content/`, `layouts/`, `assets/`, `config.yml`) and let the build regenerate it.

### 7.4 Front matter format is mixed
- **Posts** (`content/posts/*.md`) use **TOML** front matter delimited by `+++`.
- **Pages** (`about.md`, `search.md`, `archives.md`) use **YAML** front matter delimited by `---`.
Both are valid in Hugo; just match the surrounding file's style when editing. New posts created via `hugo new` get TOML (see `archetypes/default.md`).

### 7.5 Posts are drafts by default
`archetypes/default.md` sets `draft = true`. Drafts are **not built** (`buildDrafts: false` in config). Flip to `draft = false` to publish. All three existing posts are already published.

### 7.6 Future-dated posts won't appear
`buildFuture: false`. Note the existing posts are dated **December 2025**. As of now that's in the past, so they build fine — but if you date a post in the future, it silently won't publish until that date.

## 8. Common Workflows

### First-time setup
```bash
nvm use                                    # pinned Node version (.nvmrc)
git submodule update --init --recursive    # fetch the PaperMod theme
npm install                                # install project-pinned Hugo into node_modules/
```

### Run the site locally
```bash
npm run dev     # = hugo server -D (drafts included); serves at localhost:1313, hot-reloads
```

### Create a new post
```bash
npx hugo new posts/my-new-post.md
```
Then edit the file, add `tags`, set `draft = false` when ready.

### Add tags/taxonomies
Add a `tags = ['...']` array to a post's front matter. Tag pages are generated automatically; the Tags nav link already exists.

### Change site-wide behavior
Edit `config.yml` (menus, toggles, share buttons, etc.). No template changes needed for most tweaks.

### Change styling
Edit `assets/css/extended/custom.css`. For colors, prefer changing a **CSS variable** (the design tokens near the top) over writing a new rule — PaperMod cascades off those tokens. Avoid `!important`; it isn't needed with the variable-based approach. Test **both** light and dark mode.

### Customize a theme template
Find the file in `themes/PaperMod/layouts/...`, copy it to the **same relative path** under your project's `layouts/`, then edit your copy.

### Add an external nav link / CTA
Add a `menu.main` entry in `config.yml` with a full URL. The `header.html` override auto-adds `target="_blank" rel="noopener noreferrer"` for any external link. For standout CTA styling, add `params: { cta: true }` to the entry.

### Deploy
Just `git push` to `main`. GitHub Actions builds with Hugo and deploys to Pages automatically. Watch the run in the Actions tab. You do **not** manually touch `public/`.

## 9. CI/CD Pipeline (`.github/workflows/hugo.yml`)

Triggered on push to `main` (or manually via `workflow_dispatch`). Two jobs:

**build:**
1. Installs Hugo Extended `0.146.0` (pinned).
2. Installs Dart Sass (for PaperMod's SCSS).
3. Checks out the repo **with submodules** (`submodules: recursive`) and full history (`fetch-depth: 0`, needed for `.GitInfo`/`.Lastmod`).
4. Runs `hugo --gc --minify --baseURL <pages-url>` with timezone `America/New_York`.
5. Uploads `public/` as a Pages artifact.

**deploy:** Publishes the artifact to the `github-pages` environment.

Concurrency is set so production deploys aren't cancelled mid-flight.

## 10. Your First Hour Checklist

1. `nvm use` then `git submodule update --init --recursive` then `npm install` — set up the pinned toolchain and theme.
2. `npm run dev` — confirm the site runs at `localhost:1313`.
3. Open `content/posts/` and read the three existing posts to learn the voice/format.
4. Skim `config.yml` top to bottom — it's the fastest way to learn what's toggled on.
5. Open `assets/css/extended/custom.css` and read the design-tokens section — this is where the brand colors live.
6. Make a trivial change (e.g., edit `homeInfoParams.Content` in `config.yml`), see it hot-reload.

Once you can run the server, edit a post, and understand two ideas — templates override by mirroring the theme's paths, and colors are themed via CSS variables — you're ready to contribute.
